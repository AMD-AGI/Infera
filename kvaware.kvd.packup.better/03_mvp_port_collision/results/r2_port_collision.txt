=== THE FAILURE: decode Rank-0 scheduler died during init ===

    zmq.error.ZMQError: Address already in use (addr='tcp://*:32765')
    RuntimeError: Rank 0 scheduler died during initialization (exit code: -3)

Note `tcp://*` — WILDCARD, all interfaces. That distinguishes this from the
round-r1 crash, which was `tcp://127.0.0.1:30235` (loopback) and came from
sglang's own --port arithmetic. Same exception class, different origin,
different fix. Do not conflate them.


=== ROOT CAUSE ===

Both legs' --kv-events-config carried the SAME endpoint port:

    --kv-events-config {"publisher": "zmq", "endpoint": "tcp://*:32764", "topic": "kv-events"}

With --dp-size 4 sglang binds one KV-event publisher per DP rank at
`base + attn_dp_rank`:

    leg A (prefill) -> 32764, 32765, 32766, 32767
    leg B (decode)  -> 32764, 32765, 32766, 32767      <- every one collides

The crash lands on 32765 = base+1, i.e. DP rank 1's publisher, because rank 0's
bind of 32764 happened to be won by the leg that started first.

That base comes from `infera/common/net.py:free_tcp_port_block(count)`, which
before the fix:

  * scanned DOWNWARD from a FIXED start, `ip_local_port_range.low - count`
    (= 32768 - 4 = 32764 on these boxes), and
  * released its probe sockets in `finally` BEFORE returning.

So two callers saw the identical free block and both returned it. **Not a race
— deterministic.** Ten consecutive calls to the pre-fix function return the
same number every time (see results/mvp_port_block.txt).

The function is reached only from `worker.py:77`, i.e. only when
`enable_kv_events` is on. **It is a kvaware-path bug.** Turning kvaware off
makes it unreachable — which is also why nobody had hit it before.


=== THE MVP, PRE-FIX (reproduced again on 2026-07-31, results/mvp_port_block.txt) ===

    OLD bases: [32764, 32764, 32764, 32764, 32764, 32764, 32764, 32764, 32764, 32764]
    distinct: 1 -> FAIL (bug reproduced)


=== THE FIX ===

`0001-free_tcp_port_block-randomise-scan-start.patch`. Try
`_PORT_BLOCK_TRIES = 64` randomly-chosen bases in `[1024, low - count]` first,
then fall back to the original exhaustive downward scan so the function still
never fails while a block is genuinely available. Signature and socket
semantics unchanged.

Post-fix, in-container:

    >>> [free_tcp_port_block(4) for _ in range(6)]
    [12457, 4265, 24310, 16567, 28874, 29547]

And live, in the next round: the two legs registered `tcp://…:17213` and
`tcp://…:31215`, both reached "ready to roll".


=== TWO ALTERNATIVE FIXES, TESTED ON THE NODE AND REJECTED ON EVIDENCE ===

Recorded so nobody re-proposes them. Both were caught by running a 6-line MVP
BEFORE shipping a change — which is the only reason neither shipped.

(1) HOLD THE RESERVATION until the child binds.

    Rejected: the probe binds `127.0.0.1:P`, but the sglang child binds
    `0.0.0.0:P` (zmq `tcp://*`). Live MVP:

        reserved 127.0.0.1:29600
        child bind 0.0.0.0:29600 -> BLOCKED errno=98  <-- holding would break our own child

    Holding the block locks out the very process it was reserved for.

(2) RESERVE ON 0.0.0.0 WITH SO_REUSEADDR so the child can take it over.

    Rejected: then the reservation is not exclusive either. Live MVP:

        reserved 0.0.0.0:29700 (SO_REUSEADDR, no listen)
          other leg probe  -> OK   <-- BAD, collision still possible
          our child        -> OK

    A second probe takes the same port anyway, so the collision is back.

CONCLUSION: exclusivity and let-the-child-take-over are mutually incompatible
here, so the reservation MUST be released before returning. What remains
fixable is the DETERMINISM of the scan start. Hence "randomise".


=== A THIRD THING THAT WAS TRIED AND IS THE WRONG KNOB ===

`--kv-events-bind` was tried as a workaround. It does not help: that flag
controls INFERA's own publisher socket, not the port passed to sglang.
`worker.py:77` ignores it for the --kv-events-config computation. Reverted
after re-reading the code.

`--kv-events-bind` does fix a DIFFERENT, adjacent collision — its default
`tcp://0.0.0.0:5557` is identical on every leg, so two co-located legs fight
over it. That is why the later rounds give each leg its own (5557 / 5657). Two
separate port problems, one flag apart. Fixing one does nothing for the other.
