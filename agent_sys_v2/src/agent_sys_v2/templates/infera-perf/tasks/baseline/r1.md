## 任务描述

- 在我们的集群上，用与 InferenceX 相同的客户端和口径，测出用户配置（`rules/project.md` 的部署形态）的曲线：这是 v0，台账的基线系列。
- 上下文见 @intake/r1 的 brief；机器由 intake 分配（任务配置里的 machines）。

## 要做的事

1. 环境预检：节点、镜像（记录 digest）、权重、RDMA 和 CPU KV 层探针（读回校验）。
2. 质量门（skill infera-quality-gate）：smoke、GSM8K、真实（不强制）MTP 接受率。
3. 工作点先跑 AgentX fast 冒烟，再跑正式 3600 s；同节点复测一次、跨节点再测一次，得到噪声。复测的点转换时加 `--label v0-rep1`、`--label v0-rep2`（同一系列同一并发的结果重名时转换会报错，不会覆盖）。
4. 其余并发点从高往低扫（约 ×0.7），KV 悬崖附近加密；每个点用 `"$AGENT_SYS_PYTHON" -m agent_sys_v2.ledger agentx <run 目录> --out "$AGENT_SYS_WORKSPACE/results" --series v0 --round 1 --role baseline` 写进台账。
5. 快速验证标定 `calibration.json`：fast 相对正式的偏移和排序是否一致；dstep 每步变化 1 ms 对应多少 ΔY（Little 模型）；各级的耗时和噪声底（格式见 skill infera-round）。
6. `stack.json`：v0 的栈清单（镜像 digest、各组件 SHA、kit 参数、客户端版本），`"version": "v0", "sealed": true`。
7. 测量期间常开系统采样（GPU busy、功耗、时钟、NIC 字节、pidstat），profile 会直接用。
8. 对齐门槛：同配置对 IX 参考 ±10% 以内或能解释差异；本地复测 ≤ 2%；正式窗口内无 JIT、0 次 KV 传输失败、失败请求 < 10%。harness 写成项目的 skill `bench-<名>`（或直接改进 Infera kit），后续任务引用，不再复制。

## 交付

- `report.md`：以"## 结论"开头：v0 曲线和工作点数值、噪声、与对标的差距及原因、标定结果、生效配置和复现命令。
