## 任务描述

- 这是一个新项目的第一个任务：把我要优化的东西问清楚，并写成后面每个任务都能直接用的上下文。本轮的其余任务（对标、基线、profile、plan）已经建好，都在等本任务审核通过。
- 问卷模板：项目的 skill infera-round 的 `questionnaire_r1.md`（22 行，标 ★ 的必答）。

## 授权

本任务可以写本任务工作区以外的这些文件（其余照约定只写本任务工作区）：
- 项目的 `project.yaml`：`goal`、`machines`、`round`、`ledger.working_point`（以及口径和问卷不一致时的 `ledger.primary`、`ledger.x`），其余键不动；写完确认它还能解析（验收检查会读）；
- 项目的 `rules/project.md`：把所有 `<待 intake 填写>` 占位换成问卷的回答；
- 项目的 `skills/cluster-<集群名>/SKILL.md`：集群操作手册（节点、分区和 QoS、RDMA 网卡、CPU KV 层、本地盘和日志位置、外来容器的处理、探针结果），frontmatter 写 name 和 description；
- 第 1 轮 baseline 和 profile 两个任务的 frontmatter 里的 `machines`（任务文件在 tasks/baseline/、tasks/profile/ 下，名为 r1.md），只改这一个键，不改它们的 prompt。

## 要做的事

1. 预调研（不占 GPU，几分钟）：权重目录和 config.json 的量化配置；InferenceX 上同模型、同精度、同硬件的条目、镜像和 recipe；可达节点的状态（ssh、`rocm-smi`/`amd-smi`、`docker ps`、RDMA）；`repos/Infera/examples/` 下可用的 kit。
2. 按模板写工作区的 `questions.md`，"建议"列填成查到的具体值和理由，然后结束这一轮等我回答。
3. 拿到回答后逐项校验（问卷"拿到回答后的校验"一节）；不通过的追问，或按建议处理并在 brief 里写明。没有现成 kit，或后端是 SGLang/vLLM（Infera 还没有它们的 AgentX 运行器）时，在 brief 里写清楚：基线之前要先起草一个 develop 任务做 bring-up（草稿，等我决定）。
4. 按问卷"intake 的产出"一节写项目文件；给第 1 轮的 baseline 和 profile 分配机器。

## 交付

- `report.md`：以"## 结论"开头：一页 brief（模型、部署、负载、目标口径和工作点、对标、预算、范围、风险）、校验记录、改了哪些项目文件、替我做的决定。
