## Motivation

With OffloaderV2 in `cpu` mode (`--offload-group-size/--offload-num-in-group/--offload-prefetch-step`, `--offload-mode cpu`, the default mode), each offloaded MoE weight is copied to the device on onload by `_CpuParamOffloader.create_device_tensor`:

```python
return self._param.to("cuda", non_blocking=True)
```

`.to()` returns a new tensor, so Python attributes set on the host `Parameter` are not carried over. During forward, `functional_call` substitutes this device tensor for `layer.w13_weight` / `layer.w2_weight`, so code that reads attributes off the weight sees the bare copy. `is_shuffled` is one such attribute:

- Several MoE weight-processing paths tag preshuffled weights with `layer.w13_weight.is_shuffled = True` (e.g. `quantization/mxfp4.py`, `quantization/fp8.py`, `quantization/quark/schemes/quark_w4a8_mxfp4_moe.py`).
- At apply time the tag is read off the weight: `quark_w4a8_mxfp4_moe.py:493` and `mxfp4.py:1940` re-tag the `.view()` only `if hasattr(layer.w13_weight, "is_shuffled")`; `mxfp4.py:1766` and `fp8.py:3380` use `getattr(layer.w13_weight, "is_shuffled", False)`; `kernels/ops/moe/smallm_moe_gfx950/__init__.py:236` gates on `getattr(w13, "is_shuffled", False)`; aiter's `fused_moe` selects its preshuffled kernels by `getattr(w, "is_shuffled")`.

With OffloaderV2 enabled, the offloaded layers therefore reach these checks without `is_shuffled` even though their data is preshuffled, while the non-offloaded layers keep it.

Context: we found this by code reading while running GLM-5.2 MXFP4 (quark W4A8 MXFP4 MoE, aiter backend) prefill on MI355X with OffloaderV2 `cpu` mode (G4/G8, K1, step 1, TP4). All of our offload runs had this patch applied, and a G4 run passed 22/23 of our internal correctness checks (greedy/sampled smoke, needle-in-a-haystack 8k-256k, multi-fact 100k; the one miss hit `max_tokens` while reasoning). We did not run an unpatched offload round, so we have no end-to-end measurement of the unpatched behavior; the evidence for the bug is the code path above and the unit test below.

## Modifications

- `python/sglang/srt/utils/offloader.py`: `_CpuParamOffloader.create_device_tensor` sets `is_shuffled = True` on the device copy when the host parameter has `is_shuffled` set. No change when the attribute is absent or false.
- `test/registered/unit/utils/test_offloader.py` (new, CPU CI `base-a-test-cpu`): builds a `_CpuParamOffloader` around an `nn.Parameter` and checks the device tensor keeps `is_shuffled=True`, and does not gain it when the parameter has none / `False`. To run on CPU-only runners it disables pinning in `_move_param_to_cpu` and patches `torch.Tensor.to` so that a `"cuda"` target returns a fresh CPU copy (like the real H2D copy, a new tensor without the source's attributes).

Scope: only the `cpu` mode is changed. `shm_cpu` and `sharded_gpu` move the parameter to `meta` via `_move_param_to_meta`, which also does not copy `is_shuffled`; fixing those would need the flag captured before `post_init`. They are not covered here because we have not run them.
