## 四、关键数据（tok/s/GPU @ 交互 p90）

| 配置 | 结果 | 说明 |
|---|---|---|
| 1P(PP8) + 1D(TP8) C208（pkg kit，16 卡） | **56,593 @ 70.9** | 最高；瓶颈在 prefill 长上下文计算（BOTTLENECK 4b） |
| 同上 + 内核 MoE 调优行 + absorb（不加 KV 上限） | 56,595 @ 78.2 | 吞吐持平、交互 +10% |
| 第二版 Pareto（kit v2，单节点 4+4，DP 均衡） | 53,460 @ 65.4（K3 C104）… 23,530 @ 106.8（K5 C32） | 5 个点，PR #235 描述里的表 |
| 2P1D C208 / 4+4 两节点 C104 | 54,094 @ 65.7 / 53,666 @ 61.9 | |

PP8 瓶颈要点：上下文到每批约 25 万 token 时 prefill 单级耗时 140 → 310 ms（流水线是满的，没有空泡）；decode 在握手时就预分配整段 KV，
排在 prefill 队列里的请求占住 decode KV（每 rank 在跑约 6-7、等传输约 11），KV 九成时间满。decode 变快只提高交互。
