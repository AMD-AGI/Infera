# 会话亲和代码复核（2026-09-28）

复核结论：当前会话亲和方案可以进入性能验证。首次选取保留 Infera 原评分；绑定按模型和 P/D 角色隔离，固定到 RouteTarget，未绕过缓存查询、需求预约或 ActiveGuard。R1 仍在 P 响应体结束时释放 P 负载。

逐项检查了：显式 header 传递、无 header/关闭模式、并发首次选择、空闲 TTL 和活跃租约、worker/rank 变化、旧失败回调的代数保护、P/D 分离释放、HTTP/NATS 单次和流式失败路径。全局会话表锁不覆盖模型请求；选择时仅使用对应会话锁，命中后释放锁再执行固定目标的策略记账。当前实现不添加主动拥塞迁移。

本次发现并修复一个边界问题：NATS 流中错误帧会被编码成正常 SSE 数据，原先仅依赖字节流 Err 的检查不能使绑定失效。现在在编码前检查 Error、失败 Done 和缺少终止帧的断流；正常 Data/成功 Done 保留绑定。覆盖混合部署和PD Decode流，并补齐混合部署首帧/非流式终止处理。去掉了 Lease 中重复的失效逻辑。

新增回归测试后，286项单元、26项HTTP功能、4项额外集成、14项render probe测试通过；4项依赖外部服务的原有测试未运行。记录见 review-tests.txt。本轮性能使用HTTP；此次修正不改变正常HTTP的选择公式。

实验配置沿用已提出的R1＋P-only会话亲和、TTL3600、C80/4K、权重20/2、P HiCache1.5、D HiCache关闭。用户已授权在复核通过后执行，无需再次等待配置确认。压测环境生成器已显式传递 AIPERF_HTTP_X_DYNAMO_SESSION_ID_FROM_CORRELATION_ID=true，并将该项作为与G0的预期差异核对。原有数据集、依赖约束和负载参数保留。

正式前仅重启P以开启HiCache，复用健康D。上线后检查实际配置、少量请求以及会话计数，再启动884条预热和3600秒正式窗口；持续人工观察进程、队列、请求进度和错误。辅助观测失败不会自动停止健康的推理服务。
