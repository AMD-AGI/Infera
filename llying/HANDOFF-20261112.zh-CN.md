## 三、规则与教训

- 公开操作（PR 评论、at 人、改描述、转 ready）先问用户；推送到自己的 PR 分支在用户授权的任务范围内可以做。
- 登录节点不跑重任务；编译、测试都放到计算节点（holder 排队任务或 sbatch）。
- holder 35609 属于 kernel 会话，用 `/apps/liyingli/holder/queue/` 排队任务，不要和它的任务同时占 GPU；`srun --overlap` 只用于轻量 CPU 任务且队列为空时。
- **推送前先拉取 main 查冲突，推送后和发评论前用 `gh pr view --json mergeable,mergeStateStatus` 确认可合并；推送后测试工作流不出现，先查可合并状态。**
- 改文件和 git 提交不要放在同一批并行执行（会提交到改之前的内容）。
- Mooncake 仓库的 git 命令都加 `-c gc.auto=0`（浅克隆，自动 gc 很重）。本机 git 2.34 不支持 `merge-tree --write-tree`，用三参数写法。
- 容器里用 Mooncake RDMA：镜像的 libionic（ABI 4）和宿主机内核驱动（ABI 1）不匹配，要挂载 `/usr/lib/x86_64-linux-gnu/libionic.so.1.1.39:/usr/lib/x86_64-linux-gnu/libionic.so.1.0.54.0-149.g3304be71`。
- Mooncake 的 `rdma_transport_submit_task_test` 在 HIP 编译下编不过（HIPify 后找不到 `rdma_test_peers.h`，main 也一样），用 CPU-only 编译跑；`NoDuplicateSlice` 依赖测试执行顺序。
- srt-slurm 主工作区里有本地 `srtslurm.yaml`（AUS 配置），会让全量 pytest 卡在 mock sweep；全量测试用干净的 worktree 跑。
- sglang PR 的 AMD CI 不带 `--continue-on-error`，一个文件失败后该分片后面的测试不会执行；PR 作者可以用 `/rerun-failed-ci` 重跑失败项。
