## 1. 当前状态

- **最高吞吐**：E10 = yihou llr35 栈 + prefill 补丁 v3 / E1 / E10，AgentX C104 **51,374 tok/s/GPU**（crusoe 138 → 140）。

- **根因（已在 141 上用实验确认）**：镜像在 HIP 上为 DSA 模型每个 batch size 捕获 dense / sparse 两套 decode graph，**每个 DP rank 按本地最长上下文各选一套**，
  同一步里不同 rank 回放不同的 graph，graph 内注册了输入地址的 aiter collective 读到对端另一套 graph 的旧缓冲。E11 的乱码（26 / 200）由此而来，
  拷入或所有 rank 固定一套 graph 后为 0。过程：`car-copyin-141-20261103/README.zh-CN.md`。E10 的低频"开头坏"很可能是同一机制（同形状），**尚未在跨机部署上验证**。
- **通用修法**（准备提给 SGLang，上游 main 同样有这个问题）：`dp-graph-variant-fix-20261103/`。
  (1) 只给 DECODE 模式的捕获建两套 graph（TARGET_VERIFY 的两套执行完全相同的 kernel）；(2) DECODE 模式下各 rank 用 DP attention MLP sync 表里新增一列的全局上界选 variant，
  不读设备、不加通信。6 个文件，`patches/fix.diff`。
- **已验证**：单元测试 26/26（按 fdbafb60 重建的镜像，crusoe Slurm 作业 261868）；重建镜像的 11 个基线文件 md5 全部与 `patches/BASE_MD5SUMS` 一致。
