# Weekly report: GLM-5.2 AgentX PD on MI355X (11-03 – 11-10)

Throughput in tok/s/GPU (InferenceX AgentX, 3600 s scoring window); interactivity = p90 tok/s/user. Sources: `dp-graph-variant-fix-aus-20261103/`
(RESULT, STATUS, REPORT-20261106 / 09 / 10, BOTTLENECK-PP8, KERNEL-PLAN / KERNEL-PROGRESS), `dp-graph-variant-fix-20261103/`, `car-copyin-141-20261103/`,

## 1. Highlights

- **Peak throughput 51,374 → 56,593 (+10.2%)**: E10 4+4 C104 at the start of the week → 1P(PP8) + 1D(TP8) C208 (16 GPUs).
- **Second Pareto (kit v2, one-node 4+4) is above the first one (PR #210) everywhere**: +17% to +70% at equal interactivity; it is also above
  ATOM 4P4D (PR #209) at every point.
- **Correctness**: root cause of the E11 garbled output found and fixed generically (sglang#48302); cross-node validation 0 FAIL; the remaining
  wrong answers are the model's own (same as stock SGLang with the official FP8 weights).
- **PP8 is prefill-bound** (long-context prefill compute), so faster decode kernels raise interactivity, not throughput.

## 2. Optimizations that raised throughput

| Optimization | Measured gain |
|---|---|
| Decode graph-variant fix (all DP ranks replay the same dense / sparse graph), which makes E11 correct: MoE combine via aiter reduce-scatter in the graph | 50,797 → 53,609 (**+5.5%**, same node pair) |
| Draft MoE in FP8 with the sglang#45800 backport (real MTP acceptance 1.2 → 3.6) | 52,830 → 53,666 (**+1.6%**) |
| `MC_DISABLE_HIP=1`: same-node KV goes over RDMA loopback, not Mooncake's HIP copy (~1 GB/s) | one node 40,807 → 53,209 (**+30%**, now equal to two nodes) |
| Router decode DP balance (request weight 400k) | **+0.7% to +2.3%** throughput and +5% to +10% interactivity at C32–C104 |
| MTP draft steps by load (K5 up to C64, K3 from C88) | C64 41,557 → 42,356 (**+1.9%**) |
| Topology: 2P1D, then 1P(PP8) + 1D(TP8), C208 | 53,666 → 54,094 → **56,593** (+4.6% over 2P1D, interactivity 65.7 → 70.9) |

Tried without a gain: dense-layer online FP8 (−0.1%; small-M FP8 GEMM reaches only 1.8 TB/s), hrrn prefill scheduling (−4%), aiter per-token draft
MoE kernel (±0.2%), 1P2D with 12 GPUs (−5% to −16% at equal interactivity, single PP4 prefill is the limit).
