# prefill FP4 MoE kernel 效率：可行性分析（11-27，纸面）

结论先说：**prefill 的 FP4 MoE 离硬件上限还有约 2 倍空间，这是当前架构内唯一还大的一块**（MoE 约占 prefill 计算的 25%）。但能不能拿到，取决于两件事：(1) 生产里加大 prefill 批次时，MoE 每 token 的开销有没有像调优表那样下降（a51 的结果说明没有，原因待查）；(2) 剩下的差距要 aiter 的 kernel 工作，不是我们调配置能拿到的。建议先做两个便宜的实测（下面第 4 节），再决定是否投入。

## 1. 现在有多快（a54 prefill trace，C152，每 PP 级每步 4096 token）

| kernel（生产里实际用的是 asm 版） | 每层每步 | 计算量 | 达到 |
|---|---|---|---|
| `mfma_moe1_silu_mul_afp4_wfp4 … t64x128x256 … v33`（gate_up） | 827 µs | 4096 × 9 × 2 × 4096 × 6144 = 1.86 TFLOP | 2.2 PFLOPs |
| `gemm2_a4w4_port … persist`（down） | 584 µs | 4096 × 9 × 2 × 2048 × 6144 = 0.93 TFLOP | 1.6 PFLOPs |
| 合计 | 1.41 ms | 2.78 TFLOP | 2.0 PFLOPs |

（top-9 = 8 个路由专家 + 合并进来的共享专家；257 个专家。）

## 2. 上限在哪里

- **权重读取**：每层 257 × (4096 × 6144 + 6144 × 2048) × 约 0.53 B（MXFP4 + scale）≈ 5.1 GB，按 HBM 约 8 TB/s → **0.64 ms**；
- **计算**：2.78 TFLOP，按 MXFP4 峰值约 9–10 PFLOPs → **约 0.3 ms**；
- 所以 4096 token 一步的下限约 0.64 ms（读权重决定），实际 1.41 ms，**约 2.2 倍空间**；批次越大，权重读取被摊薄，下限越接近计算的 0.3 ms。

## 3. aiter 自己的调优表说明"批次越大越划算"（`glm5_fp4_tuned_fmoe.csv`，6144 / 2048 / 257 / top-9）

| 每次的 token 数 | 总时间（表里是 FlyDSL kernel） | 每 token | 达到 |
|---|---|---|---|
| 4096 | 1529 µs（生产用的 asm 版 1411 µs） | 0.373 µs（asm 0.344） | 1.8 PFLOPs |
| 8192 | 2327 µs | 0.284 µs（−24%） | 2.4 PFLOPs |
| 16384 | 4029 µs | 0.246 µs（−34%） | 2.8 PFLOPs |
| 32768 | 7359 µs | 0.225 µs（−40%） | 3.0 PFLOPs |

按这个表，prefill 批次从 4096 加到 8192，MoE 每 token 便宜约 17–24%，折合 prefill 吞吐约 +4–6%。**但 a51（批 8192 / 阈值 4096）实测 prefill 吞吐没变**（30.4k 对 30.2k tok/s），整体 −1.3%。可能的原因（未验证）：实际批次没填到 8192；或者批次变大后 MoE 选了表里的 FlyDSL kernel 而不是更快的 asm；或者注意力 / indexer 部分随批次变贵，把 MoE 的节省抵消了。a51 没有 trace，所以现在分不清。

## 4. 建议的可行性实测（都很便宜）

1. **单卡 MoE 微基准**（约 1 h）：在生产路径上（同样的 aiter 版本、同样的 kernel 选择）测 4096 / 8192 / 16384 token 的 FP4 MoE，确认每 token 开销随批次下降多少，以及 8192 时选的是哪个 kernel。
2. **批 8192 的 prefill trace**（约 2 h，一次 C152 运行加 `PTRACE=1`）：看实际批次有多大、MoE 每 token 时间、注意力 / indexer 有没有变贵。如果 MoE 确实变便宜而别的部分抵消了，就知道该往哪里查；如果批次没填满，就是调度问题（比较好修）。
3. 另一个 agent 在 aus 集群上用 nightly 镜像（更新的 aiter）复现 a49，**它的 prefill MoE 时间可以直接拿来对比**，看新版 aiter 有没有更快的 FP4 MoE。

## 5. 收益与投入

- 收益上限：MoE 快 2 倍 → prefill 计算少约 12% → 吞吐约 +12%，但会先撞上 decode KV（约 +10% 处），所以实际约 **+8–10%**；与 HiSparse 叠加才能更高。
- 投入：实测 1、2 约半天；如果原因是调度或 kernel 选择，修起来是几天的事；如果要改 kernel 本身，是 aiter 团队数周的工作，我们这边只能提需求和数据。
