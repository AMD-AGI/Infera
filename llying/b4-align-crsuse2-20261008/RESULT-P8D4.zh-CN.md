# 1P(TP8) + 1D(TP4) C80 结果

运行：`b4-crsuse2-136-138-d4-20261009T0632Z`（P 136 GPU 0–7，D 138 GPU 0–3），共 12 张卡。除 D 外
与 B4 对齐配置相同；D 按 aus 的 B5 设计：TP4/DP4、每 rank chunk 4096、max-running 256、graph bs 256。
对照是同集群、同配置的 P8D8（`RESULT.zh-CN.md` 的运行，16 张卡）。数据在
`results/b4-crsuse2-136-138-d4-20261009T0632Z/`，对比由 `scripts/compare_b4.py … p8d8` 生成。

## 结论

这个负载在 C80 下被 D 的 KV 容量卡住，P8D4 不可取：

- 完成请求 7,287 对 10,644（−31.5%），错误 0；每 GPU 吞吐 Output −8.8%（156.4 对 171.4），
  Total −14.5%（19,259 对 22,521）。
- TTFT p50 6.28 对 3.40 s（+85%），p90 57.2 对 8.5 s（+577%）。ITL p50 19.5 对 14.2 ms（+37%）。
- D 每 rank KV 2,111,808 tokens，4 个 rank 共约 845 万，是 P8D8（8 × 3,003,520 ≈ 2,403 万）的
  35%。平均输入约 11–12 万 tokens 时，1,597 个请求（占完成数 22%）因 D KV 预算等待分配，D 分配
  等待均值 15.9 s、p90 52 s；P 的 bootstrap 等待随之变长（均值 15.9 s）。
- D 本地前缀复用从 89.2% 降到 35.3%：KV 紧张时 D radix 的历史前缀被逐出，更多 KV 需要重新传输。
- D 生成时间 +29%：每个 D rank 承担的运行请求约为 P8D8 的两倍。
- P 端没有成为瓶颈：P 排队均值 −8%、前向 −13%，P 传输尾持平，是被 D 限流后负载变轻。
