# B4 在 crsuse2 上的对齐结果

运行：`b4-crsuse2-136-138-20261009T0317Z`（P 136、D 138），C80，正式窗口 3600 秒，warmup 每 lane
10，模拟接受长度 3.61。数据在 `results/b4-crsuse2-136-138-20261009T0317Z/`，对比由
`scripts/compare_b4.py` 按 `../experiment-summary-20261008/build_report.py` 的取数方式生成，
B4 一列与汇总表 `metrics.csv` 的值一致。

## 结论

- 吞吐对齐在 1% 以内：Output token/s/GPU 171.43 对 171.95（−0.30%），Total −1.03%，完成请求
  10,644 对 10,728（−0.78%），取消 11 对 11，错误 0 对 0。工作量相同（平均实际输入 −0.25%、
  输出 +0.49%）。
- 中位延迟接近：TTFT p50 +5.9%（3.40 对 3.21 s），ITL p50 −2.1%。
- 尾部略高：TTFT p90 +8.2%（8.45 对 7.81 s），ITL p90 +6.4%（21.45 对 20.16 ms）。
- 两边各只有一轮，aus 自身的轮间波动没有测过，几个百分点的差异不能归因到集群。

P 端更快或持平，传输持平；差别集中在 D 端：40 个请求（0.4%）因 D KV 预算等待分配，使 P 的
bootstrap 等待变长，这与 TTFT 尾部升高方向一致。D 端 KV 更紧的原因单轮无法确定（D 本地复用
低 2.9 pp、D 生成尾部略慢都可能有关）。缓存总命中率 96.17% 对 96.24%，P 的 host 命中占比
0.76% 对 2.01%，device 命中相应更高。

## 正确性（D 真实接受率阶段）

- B4 的已知答案检查：16/16，覆盖 P/D 各 8 个 rank。
- 扩大检查（`answer_check.py`）136 个请求：0 个传输错误；128 个跨 rank 请求错 1；第二轮
  64/64 正确且全部命中 D 前缀。所有答错都是同一道题（种子 6 文档的记录 396，答成相邻的 397），
  同 rank、跨 rank 都出现，三轮合计 11 次错 3 次，与传输和 D radix 无关。

## 与 B4 的差异

软件按 B4 的固定输入重建（SGLang 0916 + Infera `83e0f6c8` + overlay + tracing + p01/p02），
客户端设置由 aus 校验脚本逐键核对与 B4 一致，数据集逐文件一致，KV 容量偏差 < 0.01%。
不同之处都由集群决定：

- Mooncake 加 v3 修复（目的端固定 rail、固定 HCA、ACK 超时 1.07 s）；
- 每 rank 共享 8 张网卡（B4 每 rank 一张；crsuse2 rail 隔离，单网卡下跨 rank 不可达）；
- `MOONCAKE_DISABLE_HIP_DMABUF=0`（网卡驱动不同）；
- 虚拟机，主机内存 2,752 GB（aus 3,023 GB）；router 同一 commit 重新编译。
