## 一、搬迁暴露的四个问题（已修，但会重犯）

### 1. 外层目录不是包根，指过去是「加载冲突」而不是「找不到文件」

`temp/ws_kernel_opt_20260901/scratch/run_pkg.sh` 的 `REPO_PKG` 还指着
`llm_e2e_performance_optimization/`。搬迁后那个目录里有**五个 `main.yaml`**
（外层 stage 1 + analyze / profiling / kernel-opt / integration 四个 demo）。

`spec_loader.YamlPackage` 会扫描包根下**除 `assets/` 外的每一个 `*.yaml`**，
所以指到容器目录不会报「文件缺失」，而是把五个包一起加载后冲突——**排查成本
高得多**。

> **规则**：`--package` 只能指向恰好含一个 `main.yaml` 的目录。搬包之后第一件事
> 是 `find <目标> -name main.yaml | wc -l`，不是 1 就别急着跑。

### 2 & 3. 报错文案和文档里的路径会悄悄过期

`llm_e2e_perf_opt_debug_workset` 的两个 shim `entry.sh` 里
`--var real_package=<abs path to ...>` 的提示文案、以及它 README 里那条 drift
警告引用的 `steps/kernel_optimization.yaml` 路径，都还指着旧位置。

代码能跑（路径是运行时用 `--var` 传的），**只有文案在骗人**——照着提示填的人
会被指到容器目录，然后撞上问题 1。

> **规则**：搬目录后 `grep -rn "<旧路径>"`，注释、报错文案、README 一起过一遍。
> 「不影响运行」不等于「不用改」。

### 4. 删代码时留下了它的理由（我自己造的）

`run_pkg.sh` 里 `export IS_SANDBOX=1` 在某次改动中被替换掉了，但它上面
**12 行「为什么必须设 IS_SANDBOX」的注释留了下来**，正好压在下面那段
「以 host user 运行所以不需要它」的说明上面。两段互相矛盾。

跑本身一直是对的（host user 下确实不需要），只有注释在骗人——而注释骗人比代码
报错更贵，因为没有任何东西会报错。

> **规则**：删一行代码时，连同解释它存在理由的注释一起删。

## 二、仍然开着的问题

### A. debug 包和真包的 validator `args` 是两份，没有任何东西保证它们一致

`llm_e2e_perf_opt_debug_workset/steps/debug.yaml` 复述了
`check_workset_shape` 的 `args`（必需文件清单、driver token、case 下限）。
**body 不会漂**（是 shim，exec 真包的 `check.py`），但 **args 会漂**。

一旦漂了，症状是：**在 debug 包里过的 workset 到真包里挂**——而 debug 包存在的
唯一意义就是提前发现这种挂。它会变成一个说谎的工具。

没解决。想解决的话得让两边读同一份 args，或者加个测试断言两者相等。

### B. 两个 agent_sys 的真 bug，只在本地绕过，上游未修

见 `bugs/001` 和 `bugs/002`。

- **001**：`spec_loader/protocols.py:15` 用 `typing.TypedDict`，pydantic 2 在
  Python < 3.12 上拒绝，而镜像里只有 3.10 → `agent-sys` **完全 import 不了**。
  一行可修（改成 `typing_extensions.TypedDict`），`typing_extensions` 已经是依赖。
  `pyproject.toml` 声明 `requires-python = ">=3.10"`，与事实不符。
- **002**：输出阶段的 validator body 拿 PRODUCER 环境行，它**遮蔽**了携带
  `AGENT_SYS_DEMO_PYTHON` 的 GLOBAL 行，于是模板推荐的
  `${AGENT_SYS_DEMO_PYTHON:-python3}` 兜底会选到 `/usr/bin/python3`
  ——一个跟 supervisor 不同、且没有 torch 的解释器。

**002 的教训比 bug 本身值钱**：我一度在 bug 记录里写「本包免疫，因为 body 只
import 标准库」。两个半句都是真的，**推论是错的**——body 只 import 标准库，然后
去 exec 一个需要 torch 的脚本。代价是三个 campaign 的判决全废。

> 现在 `check_speedup_substantiated` 会**探测**候选解释器、在每个里面试
> `import torch`、并打印它选了哪一个。猜而不说是这个坑的成因。

### C. 优化侧的测量离散度没定位

基线离散度 1–3%，优化后的 kernel 是 **10–20%**（多次测量，稳定复现这个差异）。
原因**没有查**。候选：三个 kernel launch 的调度抖动、Triton JIT 缓存状态、
共享机器上的邻居干扰。

实际后果：**单次测量不是测量**。所有对比必须 ≥5 轮取中位数。
`check_speedup_substantiated` 的 15% 容差就是为吸收这个而定的，不是拍脑袋。

### D. 并发是否压低重测数字，未验证

09-01 我在 GPU 5/6 上**并发**重测两个 handoff，得到 2.508× / 2.512×，
明显低于它们各自自报的 2.779× / 2.610×，且两个数字出奇地接近。

同期 GPU 3/4 上还有两个 campaign 在起步。**是不是并发干扰压低了数字，没有验证。**
要确认得串行重测一遍。目前只作为观察记录，**不作为结论**。

### E. 环境里的既有偏差

- `kf-mi300b` 容器相对原始镜像多了：agent_sys（装自 `/tmp/yihou/repo` 的本地
  副本，带 001 的一行补丁）、`pyyaml`（装进 `/usr/bin/python3`，为验证 002）、
  KernelForge `.[dev]` + ROCm rocprofiler-compute 依赖。
  **任何从这个容器产出的 `environment.md` 都必须写明这些。**
- `smoke_01` 的残留进程还在 GPU 1 上（09-01 我 stop 掉 supervisor 后子进程存活）。
  不碰 GPU 3/4。**没清理**，因为清理时正有正式跑在进行，误伤风险大于收益。

### F. 权限强制打开就跑不了

`AGENT_SYS_NO_PERMISSIONS=0` 时 Landlock 确实生效（ABI 3，普通
`docker run` 即可，不需要 `--privileged`），但每个 `claude_code_sdk` 任务会死在
`ConfinementNotApplied: does not spawn a command line of its own`。

**sandbox 与 SDK agent 目前互斥**，AI 叶子只能在权限关闭下跑（也就是默认）。
这是系列任务书 ISSUE 1「必须关闭权限校验模块」的真实含义——**默认就是关的，
不需要做任何事**。

## 三、跑之前的检查清单

1. `find <package> -name main.yaml | wc -l` == 1
2. `docker exec -u "$(id -u):$(id -g)"` — **不要用 root**，四个坑见
   `run_pkg.sh` 顶部注释
3. 先跑一次 `--var mock=1`。模型名写错会**挂死不报错**（实测 >12 分钟无输出），
   `--timeout` 是必需的，不是保险
4. `--var max_hours` **> 2.0**，否则 forge 静默降级（Analysis 变 static-only，
   turn cap 500→100）。注意 forge 自己的下限是 `MIN_MAX_HOURS = 1.0`，
   **不存在「跑 5 分钟」这回事**
5. 跑完看 `check_speedup_substantiated` 的判决时，**顺手确认它的 zone 下有
   `tmp/substantiate-*/{baseline,optimized}/measured.json`**。
   没有那两个文件的 PASS 意味着它没测量就放行了——这是最危险的失效模式，
   而且它曾经真的发生过。
